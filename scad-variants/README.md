# Автоматические варианты OpenSCAD

Инструмент рендерит **один `.scad` файл из контекстного меню Проводника**.
Результат создаётся рядом с исходником:

```text
любая папка/
  my_model.scad
  my_model_renders/      ← результат рядом с файлом
    index.html
    contact.png
    part-a.png
    part-a.stl
    tmp/                 временные файлы
    manifest.json
```

Постоянного watcher и отслеживания папки `SCAD` больше нет. Один запуск
проверяет только выбранный файл, рендерит его варианты и завершается.

## PNG и STL за один запуск

Для каждого варианта OpenSCAD запускается **один раз** с двумя `-o`:

```text
openscad -o preview.png -o part.stl -D part="comb" model.scad
```

OpenSCAD сам делает полный рендер геометрии и отдаёт его сразу в PNG и
STL. Это не два независимых рендера: дерево CSG вычисляется один раз.

## Manifold

По умолчанию используется портативный OpenSCAD nightly с backend
**Manifold**:

```text
C:\Users\ak\harness\tools\openscad-2026.11.23\openscad.exe
```

Инструмент сам находит свежий `tools\openscad-*\openscad.exe`; если его нет,
остаётся системный OpenSCAD 2021.01. Старый путь можно задать явно:

```powershell
--openscad "C:\Users\ak\scoop\apps\openscad\2021.01\openscad.exe"
```

Файлы портативного OpenSCAD должны иметь **Medium integrity**: если их
распаковать из-под low-integrity процесса, OpenSCAD не сможет писать в
`Downloads` и выдаст `Can't open file ... for export`. Исправление:

```powershell
icacls C:\Users\ak\harness\tools\openscad-2026.11.23 /setintegritylevel Medium /T
```

Manifold в разы быстрее CGAL. Для проверки на `liebherr_charcoal_rails_v60`:

```text
preview: 85 с (2021.01/CGAL) → 3.3 с (2026.11.23/Manifold)
полный STL: 5.0 с вместо десятков минут
```

Учти: Manifold — новый backend, и на экзотических моделях он может вести себя
иначе. Если конкретный файл падает, запусти его со старым `--openscad`.

Нюанс: при таком режиме STL получается в текстовом (ASCII) формате — его
понимают все слайсеры, но файл больше бинарного. Бинарный STL потребовал бы
отдельного запуска OpenSCAD либо локальной конвертации. Для печати ASCII STL
подходит; если нужен именно бинарный, это можно добавить отдельным флагом.

STL делается для всех обычных печатаемых вариантов. Порядок рендера —
**от большего объекта к меньшему**:

1. для уже готовых вариантов считается число треугольников в STL (и размер файла);
2. сначала запускается самый большой, затем следующий;
3. это же порядок попадает в `manifest.json`, HTML-галерею и контактный лист;
4. файлы между собой тоже сортируются по максимальному известному STL;
5. для совершенно нового варианта, у которого ещё нет STL, используется
   эвристика по тяжёлым значениям (`frame`, `assembly`, `section`, `side`,
   `comb_strip`, `body`) — после первого рендера точный размер уже известен.

Тяжёлые варианты не пропускаются; для них отдельный таймаут:

```powershell
--timeout 300          # обычный вариант
--slow-timeout 3600    # frame / assembly / section / side / comb_strip / body
```

Файлы `section*.scad` (2D-проекция) и `show_*.scad` (импорт готового STL)
по-прежнему не экспортируются в STL; варианты `preview*.scad` с `p != "h"` —
презентационные. `--stl-mode all` включает STL и для них.

Если STL не нужен, есть `--no-mesh` — тогда выполняется только быстрый
PNG-рендер.

## Имена файлов

В имя попадают только те переключатели, которые реально влияют на данную
геометрию. Если параметр внутри группы одинаковых деталей меняется, но модель
от этого не меняется, он из имени убирается.

Пример для `v41`:

```text
part-frame.png                 side не влияет
part-frame.stl
part-body.png                  side не влияет
part-body.stl
part-lid.png                   side не влияет
part-lid.stl
part-rail__side-left.png       side влияет — оставлен
part-rail__side-left.stl
part-rail__side-right.png
part-rail__side-right.stl
```

Для `v39` дополнительно остаётся `lid_style`, потому что он меняет крышку:

```text
part-lid__lid_style-hex.png
part-lid__lid_style-windows.png
part-rail__side-left.png        lid_style не влияет
```

## Одинаковые геометрии

Некоторые комбинации переключателей дают одну и ту же деталь. Например
`lid_style` может влиять только на крышку, но не на корпус. Инструмент
сравнивает достижимый код для каждой комбинации и **рендерит уникальную
геометрию один раз**. Остальные комбинации остаются в каталоге как алиасы и
ссылаются на те же PNG/STL. В логе это выглядит так:

```text
[liebherr...scad] rendering 6 unique of 16 variant(s)...
```

## Куда класть файлы

В `<workspace>/SCAD/` — можно в корень или в подпапки:

```
SCAD/my_part.scad              → SCAD/my_part_renders/
SCAD/my-project/my_part.scad   → SCAD/my-project/my_part_renders/
SCAD/my-project/lib.scad       → SCAD/my-project/lib_renders/
```

`use`/`include` ищутся относительно самого `.scad`-файла, поэтому связанные
файлы лучше держать рядом. В `SCAD/README.md` есть короткая памятка.

## Быстрый старт

```powershell
cd scad-variants

# один проход по <workspace>/SCAD
python scad_variants.py --once

# постоянное наблюдение (рендер при внешнем изменении файла)
python scad_variants.py
```

Из корня workspace то же самое для одного файла:

```powershell
python scad-variants/scad_variants.py --once --root "C:\path\to\folder" --only "model.scad"
```

Основной способ запуска — пункт **«Отрендерить варианты»** в контекстном меню
Проводника для нужного `.scad`. Постоянного watcher и папки `SCAD` больше нет.

Открыть каталог конкретного файла: `<имя>_renders/index.html` рядом с исходником.

## Что считается переключателем

Только **верхнеуровневое присваивание строкового литерала**, у которого
нашлось хотя бы два варианта:

```scad
part = "comb"; // [comb, strip, test, section]
```

Варианты берутся из:

1. списка Customizer в комментарии `// [a, b, c]`;
2. сравнений в коде: `part == "comb"`, `part == "strip"` и т.п.;
3. их объединения.

Поэтому `d = "h";` с `if (d == "h") ... else ...` тоже распознаётся, даже
если списка в комментарии нет.

Не считаются переключателями:

```scad
end_magnet = 0;          // числовой флаг
count = 3;               // [2, 3]  — числовой enum игнорируется
sizes = ["10", "12"];    // массив строк, а не переключатель
font = "Arial";          // строка без двух вариантов
```

Если строковый параметр имеет несколько значений, но код нигде их не
различает, он тоже не станет переключателем (нет способа узнать варианты).

## Что происходит при изменении

Ключ кэша считается по **достижимому коду**, а не по всему файлу:

* комментарии и форматирование не влияют на ключ;
* `if`/`else` с известным значением переключателя разворачиваются: код
  невыбранной ветки не участвует в ключе;
* неиспользуемые `module`/`function` не участвуют в ключе;
* глобальные переменные, которые не используются достижимым кодом, тоже не
  участвуют;
* зависимости `use`/`include` входят в ключ целиком.

Практический результат:

* изменили только `module a_part()` — вариант `b` не перерендерится;
* изменили только числовой `size_a`, который нужен одному варианту — второй
  вариант не перерендерится;
* поменяли комментарий — не перерендерится ничего;
* поменяли зависимость `use <...>` — перерендерятся зависящие файлы;
* добавили новое значение переключателя — отрендерится только новый вариант.

Для наглядности в логе пишется:

```
[sds_comb.scad] 7 variant(s): rendered 1, skipped 6, failed 0
```

## Результаты

Вход — `SCAD/<файл>.scad`, выход — `SCAD/<файл>_renders/`:

```
SCAD/
  my-project/
    my_part.scad
    my_part_renders/
      index.html                     варианты одного файла
      manifest.json                  ключи, значения, ошибки
      contact.png                    контактный лист
      default.png                    готовые PNG — прямо в корне
      default.stl                    готовые STL — прямо в корне
      ...
      tmp/                           только временные файлы
```

Готовые PNG и STL лежат прямо в корне `_renders`; `tmp/` нужен только на
время рендера и после завершения обработки файла удаляется.

В HTML-каталоге есть превью, значения переключателей, время обновления,
ссылка на исходный `.scad` и ссылки на STL.

Клик по основной части картинки **открывает 3D-просмотр** во всплывающем
окне почти на весь экран. В правом верхнем углу — отдельная иконка
разворота: она открывает **саму картинку** на весь экран. Курсор над
картинкой — `grab`, над иконкой — `zoom-in`. Под картинкой: селектор слота, под ним крупная кнопка **«Отправить в слот»**,
затем **«Скопировать полный путь к изображению»** и **«Скопировать полный путь к STL»**.
Кнопки «Скачать STL» больше нет.

Время в галерее показывается в читаемом виде по Москве, без суффикса:
`24.11.2026 09:54`.

Вверху есть **«Открыть папку»** и копирование пути к папке результатов.
Браузер может показать папку списком файлов; для Проводника используй
скопированный путь.

В каждой папке `_renders` создаётся ярлык:

```text
Открыть в Edge.lnk
```

Двойной клик по нему открывает этот `index.html` в отдельном профиле Edge,
не затрагивая основной браузер. Его же можно использовать из расширения
Zen/Claude Autosave для пункта «Открыть результат».

### Слоты Orca

Для замены модели в уже открытом проекте Orca есть стабильные слоты:

```text
orca-slots/
├── 1.stl
├── 2.stl
└── slots.json
```

На карточке варианта первые три слота показаны круглыми кнопками; первый
выбран по умолчанию. Кнопка **«⋯»** открывает диалог со всеми слотами и
позволяет выбрать любой другой или создать новый. Ниже — крупная кнопка
**«Отправить в слот»** и кнопки копирования путей.
Можно выбрать существующий слот или создать новый (`+ новый слот…`).
При назначении STL копируется в стабильный файл слота.

В Orca каждый объект на столе загружается из своего слота **один раз**.
После обновления слота в Orca выбираешь объект → **Reload from disk**.
Объектов может быть сколько угодно: каждому соответствует отдельный слот.

Страница **«Слоты Orca»** в верхней панели галереи показывает все слоты,
их пути и время обновления. Там же можно удалить слот. Протокол `scad-slot:`
выполняет копирование/удаление; браузер спросит разрешение на внешний
протокол, как и для 3D. Helper работает без консольного окна и показывает
тихое Windows-уведомление об успехе или ошибке.

3D-сервер запускается только по клику на картинку, а не при открытии
галереи. Браузер один раз (или при каждом запуске) спросит разрешение на
внешний протокол `scad-viewer:` — это ограничение браузера, обойти его
нельзя.

Установка протоколов:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-variants\install-viewer-protocol.ps1
```

Скрипт регистрирует три протокола:

- `scad-gallery:` — открыть сгенерированный `index.html`;
- `scad-viewer:` — открыть 3D-просмотр;
- `scad-slot:` — скопировать STL в стабильный слот Orca.

Сам HTML-каталог после рендера открывается **в обычном окне Edge** с
отдельным профилем. Панели браузера остаются на месте.

```text
state/browser-profile
```

Это касается не только 3D: весь `index.html` с карточками открывается в этом
изолированном окне. Основной браузер, его вкладки, история и сессия не
затрагиваются. Профиль отдельный, поэтому даже если основной браузер — Edge,
это всё равно отдельный процесс.

Открытие галереи работает так:

- после рендера — автоматически, если в трее включена галочка
  **«Автоматически открывать результаты в отдельном браузере»**;
- настройка хранится в `state/ui-settings.json` и читается рендерером;
- для one-shot автоматическое открытие можно отключить флагом
  `--no-auto-open` (его использует сам `scad_drop`, чтобы не открывать дважды);
- клик по тосту — через `scad-gallery:`;
- пункт трея **«Открыть результаты рендера»** — HTML в отдельном браузере;
- пункт **«Открыть папку результатов»** — Проводник, если нужна папка.

Окно без адресной строки и вкладок; закрывается своей кнопкой или `Alt+F4`.
Если Edge не найден, используется Chrome, а затем обычный браузер по
умолчанию.

После клика по картинке `scad-viewer:` запускает локальный сервер на
`127.0.0.1` и открывает Three.js-вьюер с вращением/зумом. Сервер живёт только
для этого просмотра и выключается после 30 минут без запросов. STL отдаётся
только из папки результатов; произвольные пути запрещены.

Во время рендера состояние задачи пишется в `state/progress/*.json`: сколько
уникальных вариантов всего, сколько уже готово и какой вариант сейчас
рендерится. Иконка **SCAD Render** в трее читает эти файлы и показывает
активные задачи с прогресс-баром.

## Уведомления Windows

После каждого рендера, в котором что-то было сделано, в шторку уведомлений
Windows отправляется краткая сводка:

```text
SCAD: my_part
my_part.scad
PNG: 5 · STL: 3 · вариантов: 8 · 12.3 с
```

Если были ошибки, добавляется `ошибок: N`. Уведомление приходит и от
наблюдателя, и от `scad-drop`, и от пункта контекстного меню.
Клик по уведомлению открывает **папку с результатами** (`<имя>_renders`),
а не `index.html`.

Для уведомлений нужен ярлык с идентификатором приложения. Установка — без
администратора:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-variants\install-notifications.ps1
```

Скрипт создаёт в меню «Пуск» ярлык `SCAD Render` с AUMID `ScadDrop.Render`.
Ярлык заодно запускает наблюдение за `SCAD`. Удалить:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-variants\uninstall-notifications.ps1
```

Если уведомления не появляются, проверь:

* Windows → Параметры → Система → Уведомления: для `SCAD Render` разрешены
  уведомления;
* выключен «Не беспокоить» / Focus Assist — при нём Windows подавляет тосты,
  и инструмент пишет в лог предупреждение;
* приложение не запущено в полноэкранном/презентационном режиме.

Если рендер запущен как фоновая задача DSH, Windows не выдаёт тост: процесс
работает с низким уровнем целостности и без идентификатора пакета. В логе
будет строка `toast skipped: DSH sandbox ...`. Для уведомлений запусти
`SCAD Render` из меню «Пуск» или пункт контекстного меню Проводника — эти
процессы работают вне песочницы и показывают уведомление.

Отключить уведомления для отдельного запуска: `--no-notify`.

## Команды и флаги

```powershell
cd scad-variants
python scad_variants.py --once
python scad_variants.py --once --force                # перерендерить всё
python scad_variants.py --once --only "my-project/*.scad"
python scad_variants.py --no-mesh                     # только PNG, без STL
python scad_variants.py --workers 3
```

| Флаг | Смысл |
|---|---|
| `--root DIR` | что отслеживать (по умолчанию `<workspace>/SCAD`) |
| `--state DIR` | логи и lock (по умолчанию `<project>/state`) |
| `--once` | один проход и выход |
| `--force` | игнорировать кэш (при наблюдении — только первый проход) |
| `--only GLOB` | только подходящие относительные пути; можно повторять |
| `--exclude GLOB` | исключить пути; можно повторять |
| `--mesh` | экспорт STL вместе с PNG (включён по умолчанию) |
| `--no-mesh` | только PNG, без STL (быстрее) |
| `--stl-mode` | `printable` (по умолчанию), `all` или `none` |
| `--workers N` | параллельных OpenSCAD (по умолчанию 2) |
| `--timeout SEC` | таймаут обычного варианта (300 с) |
| `--slow-timeout SEC` | таймаут отложенных frame/assembly/body (3600 с) |
| `--max-variants N` | предохранитель от комбинаторного взрыва (64) |
| `--size WxH` | размер PNG (1200×900) |
| `--camera ...` | строка камеры OpenSCAD |
| `--no-pretty` | не обрезать/подписывать PNG через Pillow |
| `--no-notify` | не показывать уведомления Windows |

## Как это устроено

1. **Токенизатор** разбирает OpenSCAD, не путая строки, комментарии и скобки.
2. **Анализатор** ищет верхнеуровневые строковые присваивания и их варианты.
3. **Проекция варианта** статически вычисляет `if`-условия с известными
   переключателями, убирает мёртвые ветки и недостижимые определения.
4. **Хэш** достижимого токен-потока + хэши зависимостей + настройки рендера
   сравнивается с `manifest.json`.
5. Если хэш совпал и PNG на месте — рендер пропускается. Иначе OpenSCAD
   запускается с `-D name="value"`.
6. PNG обрезается, вписывается в карточку и подписывается; собирается
   контактный лист и HTML.

Исходные `.scad` никогда не изменяются: значения передаются через
`-D`, а не временной правкой файла. Это безопаснее при обрыве рендера.

## Ограничения

* Отслеживаются только `use`/`include`; внешние файлы, которые читает
  `import()`/`surface()`, в ключ не входят.
* Строковый параметр без списка Customizer и без сравнений не может быть
  разобран на варианты — добавьте `// [a, b, c]`.
* Числовые enum-переключатели намеренно не разворачиваются.
* Комбинации нескольких строковых переключателей перемножаются; при
  превышении `--max-variants` файл помечается ошибкой, чтобы не запускать
  сотни рендеров.
* Камера общая (изометрический вид). Для необычной геометрии можно поменять
  `--camera` или добавить отдельный проход.
* Для футера и контактных листов нужен Pillow. Без него всё равно
  рендерятся PNG, но без косметики.
* OpenSCAD 2021.01 не понимает не-ASCII пути. Инструмент передаёт ему
  8.3-псевдонимы путей, поэтому кириллица и пробелы работают, если на томе
  включены короткие имена. Если 8.3 отключены, такой путь не отрендерится.

## Требования

* OpenSCAD 2021.01 или новее в `PATH` (или `--openscad PATH`).
* Python 3.10+.
* Pillow — опционально, но желательно.

## Проверка

```powershell
python -m unittest discover -s tests -v
```
