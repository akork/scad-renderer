# SCAD drop — рендер из контекстного меню

Основной режим — **пункт «Отрендерить варианты» в контекстном меню
Проводника** для любого `.scad` файла в любом месте файловой системы.
Постоянного watcher папки `Downloads` или `SCAD` больше нет.

Трей-иконка **SCAD Render** остаётся: в ней список недавних рендеров,
открытие превью в Edge и открытие папки рендера.

## Автозапуск

Задача Планировщика **`SCAD Render Tray`** запускает трей при входе в Windows
для текущего пользователя. Установка/переустановка:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-drop\install-tray-autostart.ps1
```

Удалить автозапуск:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-drop\install-tray-autostart.ps1 -Remove
```

Задача запускает `powershell.exe` напрямую, без `cmd`/`wscript`, поэтому окно
терминала не появляется. Внутри работает `tray-host.ps1`: он держит дочерний
процесс трея и перезапускает его по команде **«Перезагрузить программу»**.

Host и трей вызывают `FreeConsole`, поэтому у них нет консольных окон. Сам трей
работает через `ApplicationContext` + `NotifyIcon`, без формы, — в Alt+Tab его
нет.

## Запуск вручную

```text
C:\Users\ak\harness\scad-drop\start-scad-tray.vbs
```

VBS запускает `tray-host.ps1` скрыто, поэтому перезагрузка из меню работает и
при ручном запуске. Для отладки самого трея:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass `
  -File C:\Users\ak\harness\scad-drop\scad-tray.ps1
```

В режиме отладки без host пункт «Перезагрузить программу» завершит процесс, но
не поднимет его снова.

Повторный запуск не создаёт вторую иконку: скрипт использует mutex.

## Меню трея

Левый или правый клик по иконке:

```text
Активные задачи
v60.scad — 3 из 5 (60%)
[████████░░░░░░░░]
  текущий: part = "frame" (~45%)
[███████░░░░░░░░░]
────────────────────────────────────────────────
✓ Автоматически открывать новые .scad в OpenSCAD
✓ Автоматически открывать результаты в отдельном браузере
────────────────────────────────────────────────
Последний: v57.scad
Открыть в OpenSCAD
Запустить рендеринг
Открыть результаты рендера
Открыть папку результатов
────────────────────────────────────────────────
Предыдущие:
v56.scad ▸
v55.scad ▸
v54(1).scad ▸
v54.scad ▸
v53(1).scad ▸
────────────────────────────────────────────────
Открыть папку Downloads
Открыть папку SCAD
────────────────────────────────────────────────
Перезагрузить программу
Выход
```

* **«Активные задачи»** — все текущие рендеры: имя файла, сколько вариантов
  сделано из сколько, процент и прогресс-бар по всей задаче. Ниже — второй
  прогресс-бар по **текущему варианту**: пока OpenSCAD не отдаёт точный
  процент, он считается по времени прошлого рендера этого варианта и помечен
  `~`. Если прошлого времени ещё нет, бар работает как «бегущая» полоса.
  Пока меню открыто, значения обновляются каждые 2 секунды.
* Меню закрывается при клике в любое другое окно, на панель задач или рабочий
  стол — даже если оно открыто левым кликом по иконке.
* Верхний блок — три быстрых действия для **последнего** `.scad` в Downloads:
  открыть в OpenSCAD, запустить рендеринг, открыть результаты.
* Ниже — **пять предыдущих** файлов. При наведении на файл открывается
  подменю с теми же действиями.
* «Открыть результаты рендера» открывает `<имя>_renders/index.html` в
  отдельном окне Edge с отдельным профилем. Если готовой галереи ещё нет,
  пункт **неактивен**.
* «Открыть папку результатов» открывает `<имя>_renders` в Проводнике.
* Последний файл — самый свежий по времени изменения `.scad` в Downloads.
* **«Перезагрузить программу»** — полностью перезапускает трей: старый процесс
  завершается, host-цикл поднимает новый через 2 секунды. Удобно после правки
  состояния или если меню «залипло».

* Галочка **«Автоматически открывать новые .scad в OpenSCAD»** — если стоит,
  новый `.scad` сразу открывается в OpenSCAD. Автоматического рендера при этом нет.
* Галочка **«Автоматически открывать результаты в отдельном браузере»** —
  после завершения рендера галерея сама открывается в изолированном Edge.
  Настройка хранится в `scad-variants/state/ui-settings.json` и читается
  рендерером, поэтому работает и для фонового watcher, и для one-shot.
* Если галочка снята, новый файл только запоминается; его можно отрендерить
  вручную из меню.
* **«Запустить рендеринг»** — запускает рендер выбранного файла **на месте**,
  рядом с исходником в Downloads. Открывается галерея, приходит уведомление.
* **«Открыть в OpenSCAD»** — запускает реальный
  `...\openscad\2021.01\openscad.exe`, а не консольный scoop-шим, поэтому
  дополнительное окно терминала не появляется.
* **«Открыть папку Downloads / SCAD»** — Проводник.
* **«Выход»** — закрыть трей.

Отслеживается только **появление новых файлов**. Изменение уже известного
файла, повторное скачивание под тем же именем или перезапись не считаются
новым появлением. Новый путь вроде `model(1).scad` — считается.

При первом запуске все уже лежащие в Downloads `.scad` запоминаются и не
открываются автоматически. В меню они попадают как последние загрузки.

## Рендер из трея

Трей вызывает:

```text
pythonw.exe scad_drop.py --render-file "<файл>"
```

Поэтому:

* рендер идёт **в папке файла**, без копирования в `SCAD`;
* `use`/`include` работают относительно исходника;
* создаётся `<имя>_renders` с PNG, STL, `contact.png`, `index.html`;
* окно терминала не появляется;
* после завершения галерея открывается, если включена галочка
  «Автоматически открывать результаты…»; клик по уведомлению тоже открывает
  `index.html` в отдельном профиле Edge.
  (если уведомление не подавлено режимом «Не беспокоить» или песочницей DSH).

Пока файл рендерится, повторный клик по тому же пункту игнорируется.

## Старый режим с окном выбора

`scad_drop.py` без `--render-file` всё ещё умеет показывать окно
«Открыть этот файл в OpenSCAD?» с галочкой рендера. Это оставлено для ручного
запуска и старых сценариев, но **трей этот режим не использует** и запускать
его одновременно не нужно.

Старое поведение:

| Кнопка | Галочка | Результат |
|---|---|---|
| Открыть | снята | открывается оригинал из Downloads |
| Открыть | стоит | копия в `SCAD`, запуск OpenSCAD, рендер |
| Не открывать | стоит | только рендер: копия в `SCAD` |
| Не открывать | снята | файл пропускается |

## Контекстное меню Windows

Пункт в контекстном меню Проводника для `.scad`:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-drop\install-context-menu.ps1
```

Правый клик по `.scad` → **«Отрендерить SCAD (PNG + STL)»**. В Windows 11
пункт может находиться в «Показать дополнительные параметры».

Что делает пункт:

* рендерит **выбранный файл на месте**, без копирования в `SCAD`;
* создаёт `<имя>_renders` рядом с исходником — с PNG, STL, `index.html`;
* `use`/`include` продолжают работать относительно самого файла;
* открывает готовый `index.html` в браузере;
* **не показывает окно терминала** — запускается через `pythonw.exe`;
* после завершения показывает уведомление Windows со сводкой;
* использует отдельное временное состояние, поэтому не блокирует
  наблюдатель SCAD и не конфликтует с его lock.

Удалить пункт:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\ak\harness\scad-drop\uninstall-context-menu.ps1
```

Вручную тот же рендер:

```powershell
C:\Users\ak\harness\scad-drop\render-scad.cmd "C:\путь\модель.scad"
```

## Флаги CLI

| Флаг | Смысл |
|---|---|
| `--downloads DIR` | что смотреть (по умолчанию `%USERPROFILE%\Downloads`) |
| `--scad-root DIR` | входная папка рендерера (по умолчанию `..\SCAD`) |
| `--once` | один проход и выход |
| `--render-file PATH` | отрендерить один `.scad` на месте и выйти |
| `--yes` | автоматически включить рендер и не показывать окно |
| `--yes-open` | автоматически открыть в OpenSCAD и не показывать окно |
| `--openscad PATH` | путь к `openscad.exe` |
| `--no-popup` | не показывать окна; без `--yes`/`--yes-open` файлы пропускаются |
| `--scan-existing` | обработать файлы, лежавшие в Downloads до запуска |
| `--recursive` | смотреть и подпапки Downloads |
| `--extensions .scad` | список расширений через запятую |
| `--stable SEC` | сколько секунд файл должен не меняться (по умолчанию 2) |
| `--poll SEC` | период опроса (по умолчанию 2) |
| `--render-timeout SEC` | сколько ждать рендер (по умолчанию 3600) |
| `--no-open` / `--no-gallery` | не открывать браузер с каталогом |
| `--dry-run` | только писать в лог, ничего не копировать |

## Файлы состояния

Трей:

* `state\tray.json` — `auto_open`, `seen`, `recent`, `last_processed`;
* `state\tray.log` — журнал трея.

Старый watcher:

* `state\seen.json` — что уже обработано;
* `state\scad_drop.log` — журнал рендера/контекстного меню;
* `state\.drop.lock` — защита от второго экземпляра.

## Ограничения

* Трей — это скрипт, а не служба. Он запускается задачей Планировщика
  `SCAD Render Tray` при входе в Windows; вручную — через
  `start-scad-tray.vbs`.
* Иконка может оказаться в переполнении трея (стрелка «^»); в текущем профиле
  она помечена как отображаемая, но её можно перетащить на панель задач.
* Если запущен старый `scad_drop.py` watcher, он снова начнёт показывать окна
  выбора. Одновременно с треем его запускать не нужно.
* Уведомления из фоновой задачи DSH могут пропускаться; для уведомлений
  запускай трей/рендер обычным процессом вне песочницы.
